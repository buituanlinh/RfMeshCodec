# RfMeshCodec

Binary pack/unpack codec for AVR ↔ ESP32 RF mesh frames.

RfMeshCodec is a small, transport-agnostic protocol library focused on one job: convert structured binary frame bodies into wire-safe payloads and decode them back without depending on RF24Mesh or RF24Network objects.

It is intentionally low-level and protocol-first. The library handles:

- fixed-size message bodies
- little-endian field packing/unpacking
- CRC-8/MAXIM validation
- TLV telemetry and command payloads
- generic send hooks so the network layer can stay outside this library

This project is designed for embedded firmware that needs safe binary communication between AVR and ESP32 nodes without coupling directly to a mesh transport implementation.

## What it is not

This library does not implement:

- RF24Mesh routing or node discovery
- RF24Network transport logic
- retries, ACK state machines, or gateway orchestration
- high-level command execution in the app layer

Instead, it provides the codec primitives that higher layers can call from a scheduler, gateway bridge, or application state machine.

## Message families

The library defines a compact RF protocol with fixed message types such as:

- `P` / `p`: provisioning request / response
- `W` / `w`: hardware config request / response
- `G` / `g`: role/config request / response
- `T`: telemetry frame with TLV payload
- `H`: heartbeat
- `C`: command frame with TLV payload
- `Q`: ping
- `A`: ACK

The wire format is pack-oriented and uses a small header plus payload body. The field layout is defined in `src/rf_struct_defs.h` and the encode/decode helpers live in `src/rf_codec.h` / `src/rf_codec.cpp`.

## Included files

- `src/RfMeshCodec.h` – umbrella public include
- `src/rf_codec.h` – public codec API
- `src/rf_struct_defs.h` – protocol structs and message enums
- `src/rf_proto_map.h` / `.cpp` – name mapping helpers for debug/inspection

## Quick start

```cpp
#include <Arduino.h>
#include "RfMeshCodec.h"

static bool my_send_cb(uint8_t msg_type, const void *buf, uint8_t len, void *user) {
  (void)user;
  // Replace with your actual RF transport call.
  // Example: network.write(msg_type, buf, len);
  return true;
}

void setup() {
  Serial.begin(115200);

  uint8_t mac[6] = {0xAA, 0xBB, 0xCC, 0xDD, 0xEE, 0xFF};

  // Send a G-frame: config request
  bool ok = rf_node_send_G(
    my_send_cb,
    nullptr,
    1001,
    mac,
    millis() / 1000UL
  );

  Serial.println(ok ? "G frame sent" : "G frame failed");
}

void loop() {
}
```

## Sending a telemetry frame

Telemetry payloads are packed as TLV blocks. The library exposes a small TLV writer to append fields without manual byte packing.

```cpp
uint8_t mac[6] = {0x12, 0x34, 0x56, 0x78, 0x9A, 0xBC};
uint8_t tlv[32];
rf_tlv_writer_t w;

rf_tlvw_init(&w, tlv, sizeof(tlv));
rf_tlvw_put_u16_le(&w, 0x10, 245); // example sensor value
rf_tlvw_put_u8(&w, 0x1F, 1);        // example digital switch state

bool ok = rf_node_send_T(
  my_send_cb,
  nullptr,
  2002,
  0x05,
  mac,
  millis() / 1000UL,
  tlv,
  rf_tlvw_len(&w)
);
```

## Sending a command frame

Command frames use a fixed header and a trailing TLV. These are typically generated by a master/controller node.

```cpp
uint8_t cmd_tlv[16];
rf_tlv_writer_t w;
rf_tlvw_init(&w, cmd_tlv, sizeof(cmd_tlv));
rf_tlvw_put_u8(&w, RF_TLV_CMD_SWITCH0_STATE, 1);

bool ok = rf_master_send_C(
  my_send_cb,
  nullptr,
  3003,
  1234,
  1500,
  RF_CMD_MODE_SET,
  cmd_tlv,
  rf_tlvw_len(&w)
);
```

## Decoding received payloads

The library also supports decode-from-wire flow on the receiver side.

```cpp
uint8_t rx_payload[64];
size_t rx_len = 0;

const uint8_t *body = nullptr;
size_t body_len = 0;

rf_decode_status_t st = rf_decode_payload(
  RF_MSG_G_CFG_REQ,
  rx_payload,
  rx_len,
  &body,
  &body_len
);

if (st == RF_DECODE_OK) {
  rf_G_view_t view;
  rf_decode_G(rx_payload, rx_len, &view);
  Serial.print("req_id=");
  Serial.println(view.req_id);
}
```

## API highlights

Some of the most useful APIs exposed by the library:

- `rf_crc8_maxim()` – compute CRC-8/MAXIM over a byte buffer
- `rf_encode_payload()` – encode a message body into final RF payload
- `rf_decode_payload()` – validate and decode a message payload
- `rf_node_send_P_once()` – send provisioning request
- `rf_node_send_W()` – send hardware config request
- `rf_node_send_G()` – send config request
- `rf_node_send_T()` – send telemetry with TLV
- `rf_node_send_H()` – send heartbeat
- `rf_master_send_C()` – send command frame
- `rf_decode_G()`, `rf_decode_H()`, `rf_decode_C()` – parse decoded body into views
- `rf_tlvw_init()`, `rf_tlvw_put_u8()`, `rf_tlvw_put_u16_le()` – build TLV payloads

## Integration guidance

Use this library as a protocol codec only. A typical architecture looks like this:

1. transport layer receives raw RF payload
2. library validates message type, CRC, and length
3. higher-level logic decodes `rf_*_view_t` structures
4. application decides whether to send ACK, telemetry, or commands
5. library re-encodes outgoing payloads before the transport sends them

This keeps the protocol definition centralized and reusable across AVR and ESP32 codebases.

## Notes for contributors

When extending this library, keep these rules in mind:

- keep the protocol binary layout stable
- prefer fixed-size structs with explicit little-endian fields
- avoid transport code in the codec layer
- validate CRC and length before decoding payload content
- keep TLV types and messages well documented for cross-platform compatibility
